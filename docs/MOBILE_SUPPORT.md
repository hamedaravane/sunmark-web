# Mobile support and performance targets

Research date: 2026-11-10. These are provisional engineering targets, not certified minimum requirements. No physical-device benchmark has yet established the lowest supported handset. The game does not block models or operating systems based on this table.

## Design for the game being played

This is a turn-based board game. Responsiveness, readable Persian text, correct input, reliable saves and long-session stability take precedence over peak FPS. A static screen does not need continuous rendering. Thirty FPS during board motion and transitions is a reasonable project acceptance target; it is not an industry certification or a requirement to lower smooth high-end devices to 30 FPS. A three-second local menu freeze fails regardless of average FPS.

| Area                 | Provisional acceptance target on minimum-class physical hardware                                                                                                                                                                                                       |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Local input feedback | Aim for p95 at or below 100 ms; investigate any repeatable interaction over 200 ms. Measure input to visible feedback, including the canvas, separately from animation completion.                                                                                     |
| Motion               | Approximately 30 FPS with p95 frame interval at or below 40 ms during steady transitions; measure action/startup spikes separately.                                                                                                                                    |
| Idle                 | Static home submits no frames after settling. No busy polling or new decorative animation added to static pages. Full-board demand rendering is a follow-up, requiring wake/resume and asynchronous-effect coverage.                                                   |
| Memory               | No accumulating resources after warmed repeated navigation and turns. Use 80 MiB base-level texture storage and 64 MiB JS heap as initial investigation budgets, not total process-RAM promises. Browser, driver, decoded image and framebuffer memory are additional. |
| Load                 | Target usable cold home within five seconds on 10 Mbps / 150 ms RTT; report warm/offline separately. This target is not yet measured on phones.                                                                                                                        |
| Sustained play       | At least 15 minutes plus a completed match, repeated menus, background/resume and rotation without progressive slowdown, input loss, crashes or lost saves. Check thermals and battery on hardware.                                                                    |

Google's [INP guidance](https://web.dev/articles/inp) calls 200 ms or less good responsiveness (at the 75th percentile of visits). Our per-interaction p95 target is a stricter local engineering goal and is **not** the same statistic as field INP. Neither average FPS nor synthetic CPU throttling establishes those input targets.

## What the market evidence actually measures

- [Statcounter mobile OS usage](https://gs.statcounter.com/os-market-share/mobile/worldwide/), October 2026: Android 72.36%, iOS 27.61%. [Mobile browser usage](https://gs.statcounter.com/browser-market-share/mobile/worldwide/): Chrome 70.37%, Safari 21.91%, Samsung Internet 3.16%. These are web-usage shares, not a census of owned devices.
- [AppBrain's active Android model sample](https://www.appbrain.com/stats/top-android-phones), updated November 8: Galaxy A12 leads individual Android models at 1.03%. Its SDK sample covers over 100 million monthly users; a seven-day window includes phones/tablets and excludes iPhones. This is evidence to include older budget Android hardware, not proof of the single most common smartphone worldwide.
- [Counterpoint's 2025 installed-base report](https://counterpointresearch.com/en/insights/Active-Installed-Base-8-Smartphone-OEMs-Top-200-mn-Nearly-1-in-4-is-an-iPhone), February 2026: iPhones represent nearly one in four active smartphones, Samsung nearly one in five, and replacement cycles approach four years. Xiaomi, OPPO, vivo and other brands must also be represented in validation.
- [Counterpoint's 2025 sales ranking](https://counterpointresearch.com/en/insights/iphone-16-worlds-best-selling-smartphone-in-2025-apple-takes-7-spots-in-top-10-models): iPhone 16 led new sales and Galaxy A16 5G led Android. Top ten models account for only 19% of sales. New sales are not installed-base hardware requirements.
- [Counterpoint's DRAM report](https://counterpointresearch.com/en/insights/Global-Smartphone-Average-DRAM-Hits-Record-8.4GB-in-2025) reports 8.4 GB sales-weighted average RAM in December 2025. It does not establish the median RAM of active phones. There is no defensible universal average-user CPU/GPU/RAM configuration in these public datasets.
- [Statcounter Android versions](https://gs.statcounter.com/android-version-market-share/mobile/worldwide/) in October 2026 span Android 16 (38.01%), 15 (16.54%), 14 (11.35%), 13 (10.95%), 12 (7.12%) and 11 (5.91%). OS support should span this distribution and the older budget tier, rather than only the newest release. Other SDK surveys use different samples and produce different shares; do not combine denominators.

## Provisional hardware/browser floor

| Platform                  | Engineering target                                                                                                                                                                                     | Why include it                                                                                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Android minimum class     | 3 GB physical RAM; Cortex-A53/A55 octa-core class, Helio P35 / Exynos 850; PowerVR GE8320 / Mali-G52 class; approximately 720p display; Android 10+ with a maintained Chrome release and working WebGL | Older active budget hardware, not flagship sales averages. Samsung's A12 AT&T variant has 3 GB, so a 4 GB-only floor would exclude it.                |
| Android recommended class | 4 GB or more; Helio G85 or better; current Chrome / Samsung Internet                                                                                                                                   | Covers inexpensive devices from Samsung and Xiaomi as well as higher tiers.                                                                           |
| iOS minimum class         | A12 / iPhone XR or newer; iOS 17+ / Safari 17+ with working WebGL                                                                                                                                      | Deliberately reaches below the reported iPhone 11 issue. Validate the smallest SE layout separately. RAM is not exposed reliably to web applications. |
| Higher tiers              | Modern Android and iPhone; desktop browsers                                                                                                                                                            | Preserve text clarity, artwork and responsive layouts; gains on weak devices must not break stronger ones.                                            |

Sources: [Samsung A12 official datasheet](https://image-us.samsung.com/SamsungUS/samsungbusiness/pdfs/datasheet/Galaxy_A12_Series_Datasheet_ATT.pdf), [MediaTek P35](https://www.mediatek.com/products/smartphones/mediatek-helio-p35), [Samsung Exynos 850](https://image.semiconductor.samsung.com/content/samsung/p6/etc/exynos/file/solution/MobileProcessor-850.pdf), [Redmi 13C specifications](https://www.mi.com/uk/product/redmi-13c/specs/), [Apple XR specifications](https://support.apple.com/en-us/111868). Chrome 139 and newer [require Android 10+](https://support.google.com/chrome/thread/352616098/sunsetting-chrome-support-for-android-8-0-oreo-and-android-9-0-pie?hl=en). Older browsers remain best effort, not blocked. These version choices are support targets, not assertions that every combination has been tested or still receives OS security updates.

## Implementation and repeatable checks

The starting renderer budget is selected from coarse, optional browser hints, not model names. Handhelds reporting at most 4 GB RAM or at most four logical cores start at density 1.5 / one million backing pixels with decorative water motion disabled. Unknown memory starts at density 2 / two million pixels. Strong hints retain density 3 / three million pixels; desktop retains its previous four-million-pixel limit. Browser memory hints are rounded estimates and may be absent; they are not an allocation limit or a guarantee of GPU speed. Sustained slow frames still reduce density through a 1x floor; stable 30 Hz does not trigger degradation. Layout and hit targets do not change.

Number-token backing art and unowned port emblems now share two generated textures instead of repeatedly submitting complex vector paths. Persian numbers, ownership colors and game state remain runtime data. Art, rules and gameplay motion are preserved. Static home sleep, shared source textures and bounded panel reuse remain in place. See [PERFORMANCE.md](PERFORMANCE.md).

Start `npm run browser:dev`, then run `node scripts/performance-matrix.mjs` (or append `budget-720` to select one profile). Optional `PERFORMANCE_BASELINE_URL=http://127.0.0.1:4174` compares a prior local checkout. JSON results go to ignored `output/playwright/performance/`. The script checks seeded board fixtures, density/CPU-hint combinations, draw calls, frame intervals, texture-source bytes and browser exceptions. It does not simulate an actual mobile GPU, OS, physical RAM limit or Safari; CPU throttle factors are host-relative. Use the authorized UI capture flow for real control interaction, separately from the rendering fixture.

## Remaining physical validation

Test P35 / Exynos 850 Android with 3–4 GB, G85 Android (for example Redmi 13C / Galaxy A06), a current A16-class Android, iPhone XR / SE 2020, and a mainstream newer iPhone. Include Chrome, Samsung Internet and Safari as actual browsers, plus installed home-screen mode where supported. Run startup, every menu, repeated open/close, narration, touch scrolling, construction, trading, AI turns, late-game full boards, save/load, rotation and background/resume. Measure cold and warmed input-to-present p50/p95, frame pacing during motion, memory after repeated cycles, and sustained thermals. Do not claim this floor certified until these measurements pass.

The current Linux environment only has Chromium with SwiftShader software graphics. A WebKit launch was attempted but its executable is absent; Chromium profiles with iPhone-sized viewports do not validate Safari. No new telemetry, page removals or deployment are part of this support-target change.
